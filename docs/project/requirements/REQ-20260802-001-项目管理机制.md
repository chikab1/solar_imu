# REQ-20260802-001 建立项目经理与需求落盘机制

状态：Verified  
优先级：P0  
提出日期：2026-08-02  
目标版本：项目协作基线

## 1. 原始需求

由Codex担任项目经理。用户提出模糊需求后，通过对话澄清；明确结论自动写入仓库，并反馈给项目经理继续安排实施和进度。

## 2. 已确认需求

1. 用户无需先写完整技术规格，只需说明目标、现象和关注点。
2. 项目经理负责检查现状、提出关键问题、比较方案和定义验收标准。
3. 结论必须写入仓库，不能只停留在聊天记录。
4. 项目进度、阻塞、风险和下一步有统一状态表。
5. 独立分析可以拆分，但项目经理统一对用户沟通和汇总结论。

## 3. 实施结果

- 新增根目录AGENTS.md，作为后续Codex会话的持续协作规则。
- 新增PROJECT_STATUS.md，记录基线、进度、优先级和风险。
- 新增REQUIREMENT_TEMPLATE.md，统一需求、验收和测试格式。
- 新增DECISION_LOG.md，记录架构级长期决策。
- 建立docs/project/requirements目录保存逐项需求。

## 4. 验收结果

- [x] 需求沟通流程已定义。
- [x] 状态和完成标准已定义。
- [x] 需求结论有固定落盘位置。
- [x] 架构决策有独立记录。
- [x] 后续会话可通过AGENTS.md恢复协作规则。

## 5. 后续使用

下一次用户提出新需求时，项目经理直接创建新的REQ文件并进入Clarifying或Confirmed状态，无需用户重复说明这套管理规则。
